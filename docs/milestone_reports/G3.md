## Real Claude run (owner-approved autonomy; scratch folder with one `auth.py`; 2 attempts)
1. First attempt exposed a **design flaw**: read-only dev tasks produced a *plan*, QA (real, correct `VERDICT:` format) rejected 3× with grounded reasons ("lỗi chưa được sửa") ⇒ rework bounded at 3 runs ⇒ task FAILED, WO BLOCKED, nothing DONE (88 s, 6 runs). The safety logic worked; the prompt did not describe what read-only can deliver.
2. Fixed: read-only prompts ask for a concrete PROPOSAL and tell QA to judge the proposal. Second attempt: Fast Lane (backend_engineer + qa_engineer) ⇒ both tasks DONE in 40 s, QA PASS citing real lines of `auth.py` (it read the file), separate sessions, provider session ids stored, scratch folder unchanged.
